# Photo to spare part

Work in a separate job directory for each object, outside the plugin installation. Keep originals, evidence, and numbered revisions together. All script paths below are relative to this SKILL.md. Use the executable scripts/run to select the installed Python environment.

1. If the user has supplied media, inspect it first. For a new capture, give the short instructions in [capture and measurements](references/capture.md). Accept phone video, stills, or both. Work from the simplest capture that shows the relevant geometry.
2. Preserve the supplied media in originals/. Run `scripts/run capture evidence-01 originals/part.mov originals/width.jpg` with the actual files. Open the contact sheet, then inspect individual frames and full-size measurement photos. Read frames.json for filenames and timestamps. If a feature may be between selected views, rerun into a new evidence directory with `--start 12 --end 15 --fps 8 --limit 16` on that video before asking for another view. Use originals for fine details.
3. Identify the part's function, datums, handedness, and how it mates. Record dimensions in a job-local measurements.md with feature, value/unit, source photo or timestamp, measured/derived/estimated status and calculation where applicable. Check the visible jaws AND reading/unit for each caliper value. Use straight-on same-plane ratios anchored to a measured dimension only for noncritical details. Cross-check other views. Avoid projecting a single image scale through different depths. Identify fragments and missing faces separately from an intended repair.
4. For a critical interface without evidence, ask one specific question describing the view or caliper placement needed. Pause only geometry that depends on it. A useful answer might be a picture of the mating shaft. Never silently assume a blind bore depth, thread pitch, hole spacing or intended press fit. With no reliable scale, request one physical reference before a sized export. Document optional prototype assumptions explicitly.
5. Author a self-contained model.py with CadQuery. Define named parameters in mm and a zero-argument build() returning one valid solid. Use aligned orthogonal projections and geometric constraints (concentricity, measured offsets, repeated features) to reconstruct the shape. Compare its silhouettes and feature locations against the source views. Keep measured nominal dimensions separate from explicit print-fit adjustments. Execute only model code you authored or reviewed. The Python helper runs it as local code.
6. Run `scripts/run export model.py rev-01 --size X Y Z` with the independently intended envelope in mm, ordered by modeled axes. Inspect preview.png and validation.json, including actual extents, and verify critical feature sizes and locations against the dimension record. Correct geometry and rerun if a check fails. The exporter takes a new output path and saves the source, binary part.stl, preview and checks together.
7. Deliver links to the STL and preview, overall dimensions, material assumptions affecting fit, and any uncertain feature. Say “import as millimeters.” Distinguish file validation from physical fit. If a mating interface dominates the risk, use the same parameters to build a small test section retaining its functional depth, wall and orientation. Preserve prior revisions when updating from fit feedback. Record user-reported print results separately from the mesh report.

If scripts/run reports a missing runtime, run scripts/setup once on the modeling computer. It requires Python 3, FFmpeg and FFprobe on PATH and network access for packages.
